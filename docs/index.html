Getting started

A searchable suggestions popover for an <input> with a <datalist>. The input stays the real control: type anything, or pick a suggestion, and forms, validation and your own code see an ordinary input.

Datalynx isn't on npm yet. Once it is, install the package, import it once, and load the stylesheet.

Without a build step, load the stylesheet and one of the single files in dist/, from a CDN for example. Each has the element with every translation, about 11 kB gzipped. Load it as a plain script, which sets window.DataLynx:

Or import it as a module, whose default export is DataLynx:

Every file also comes unminified, without .min. Then wrap the input in <data-lynx>; its datalist can be anywhere in the page. Type a letter, or press ↓ to see every suggestion.

The input keeps its value, its form submission and its own input and change events. Picking a suggestion puts its value in the input, as typing it would. Datalynx doesn't style the input: it keeps your page's look, and only the popover is Datalynx's.

Search

Search works as in Platypicker. Case and accents don't matter: "zurich" finds Zürich. The letters you type match in order, the first at the start of a word and the rest anywhere after it, so initials find a suggestion: "nyc" finds New York City JFK. Text inside a word matches too, as "throw" does in Heathrow. Matches are highlighted.

A suggestion is found by its label, its value, its data-subtext and its data-icon: "ams", "amsterdam" and "netherlands" all find Amsterdam, whose value is AMS. A row found only by its value shows no highlight, since the value isn't on the row.

Strong matches come first, those where every matched part starts a word, then the rest, each in list order. Type "an": Antalya comes first, where "an" starts a word, then the others in list order, from Amsterdam (by its subtext, Netherlands) and Athens (by its initials) to Zürich (Switzerland). Rows only ever join below the ones shown, so nothing moves while you're about to pick it.
