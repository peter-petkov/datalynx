Getting started

A searchable suggestions popover for an <input> with a <datalist>. The input stays the real control: type anything, or pick a suggestion, and forms, validation and your own code see an ordinary input.

Datalynx isn't on npm yet. Once it is, install the package, import it once, and load the stylesheet.

Without a build step, load the stylesheet and one of the single files in dist/, from a CDN for example. Each has the element with every translation, about 11 kB gzipped. Load it as a plain script, which sets window.DataLynx:

Or import it as a module, whose default export is DataLynx:

Every file also comes unminified, without .min. Then wrap the input in <data-lynx>; its datalist can be anywhere in the page. Type a letter, or press ↓ to see every suggestion.

The input keeps its value, its form submission and its own input and change events. Picking a suggestion puts its value in the input, as typing it would. Datalynx doesn't style the input: it keeps your page's look, and only the popover is Datalynx's.

Search

Search works as in Platypicker. Case and accents don't matter: "zurich" finds Zürich. The letters you type match in order, the first at the start of a word and the rest anywhere after it, so initials find a suggestion: "nyc" finds New York City JFK. Text inside a word matches too, as "throw" does in Heathrow. Matches are highlighted.

A suggestion is found by its label, its value, its data-subtext and its data-icon: "ams", "amsterdam" and "netherlands" all find Amsterdam, whose value is AMS. A row found only by its value shows no highlight, since the value isn't on the row.

Strong matches come first, those where every matched part starts a word, then the rest, each in list order. Type "an": Antalya comes first, where "an" starts a word, then the others in list order, from Amsterdam (by its subtext, Netherlands) and Athens (by its initials) to Zürich (Switzerland). Rows only ever join below the ones shown, so nothing moves while you're about to pick it.

Labels and subtexts

A row shows the option's label: its label attribute or its text, or else its value. data-subtext sits beside it, in a muted color. Picking a row puts the option's value in the input, not its label, as the browser's own datalist does. So a list can show names and fill in addresses: type "grace", or "hopper", and pick her.

Options with hidden or disabled are left out, as the browser leaves out disabled ones. title on an option becomes its row's tooltip.

Images and icons

data-image on an option puts a picture before its label, such as a flag or an avatar. It's a square of --datalynx-image-size (1.25em), with the whole picture shown in it, so rows don't jump as the images arrive. Images load only once their row is near the view, and one that fails to load is hidden.

data-icon puts short text there instead, for an emoji, in a slot as wide as an image, so the labels line up. Unlike an emoji in the label, it isn't read out by screen readers. Both are decorative: the label names the option. Search finds an icon when you type its emoji, as "🍋" finds Lemon in the fruit field above; an image isn't searched.

Opening and keyboard

Typing opens the popover with the suggestions that match. ↓, Alt+↓ or a click in an input that already has focus open it even while the input is empty, with every suggestion. Focusing the input doesn't, by Tab or by the click that focuses it, so moving through a form stays quiet. Emptying the input while the popover is open shows every suggestion again. It closes when nothing matches, on Esc, Alt+↑ or a pick, and when focus leaves the input.

Focus stays in the input all along, so typing, the caret and selecting text work as in any input. The log shows the input's own events: a pick fires input and change, as typing and leaving the field would.

    The input is a combobox (role="combobox", aria-expanded, aria-controls, aria-autocomplete="list", aria-activedescendant) controlling a listbox of options, so screen readers follow the active suggestion while focus stays in the input. They hear how many suggestions match once typing pauses. Forced colors (Windows High Contrast) are supported.

    The browser's datalist

    Chrome and Firefox show their own datalist popup whenever an input has a list, whatever the CSS says. So while Datalynx enhances an input, it takes the list attribute off and sets autocomplete="off", since Firefox would show the input's form history in its place. Both go back as they were when the element is removed. Meanwhile input.list is null, and the element's datalist property has the datalist.

    Turning autocomplete off also turns off the browser's autofill for that input: Datalynx's suggestions replace the browser's. Browsers don't let a page read their autofill or form history, so it can't show in Datalynx's popover. Compare the two fields: both are name="email" with autocomplete="email" and the same suggestions, and only the first has Datalynx. Submit an address once so the browser remembers it, then try each field again.

    Validation

    An input with a datalist takes free text, and Datalynx never rejects or clears what's typed. With strict, text that matches no suggestion makes the input invalid, left as typed: the form won't submit, the browser says "Please enter a value from the list.", and :user-invalid applies. Datalynx doesn't style the invalid input; the page does, as here with a red border.

    Case and accents don't matter, and a suggestion's label counts as well as its value, as long as no other suggestion has the same label. On change, when you leave the field or press Enter, a match is corrected to the suggestion's value, firing input and change as a pick would: type "sofia" or "zurich" and press Tab. An empty field is valid; required is for a field that must be filled.

      Datalynx checks the text on input, change, focus out and a form reset, and when the options change. A script that sets input.value fires no event, so Datalynx doesn't see it: dispatch an input event after it. Turning strict off clears the message; a message the page set itself with setCustomValidity is left alone.

      Ghost completion

      With ghost, the faded rest of the first suggestion that starts with what you type shows after your text, with a small Tab key cap, and Tab accepts it. Nothing goes into the value until then, and focus stays in the field. Case and accents don't matter, as in search: type "zur" for Zürich, or "stras" for Straßburg, where ß searches as "ss". Initials and matches inside a word never ghost.

      Accepting writes the suggestion's exact value, firing input as typing would: in the airport field "zur" ghosts the label Zürich and Tab writes ZRH. The ghost shows only once you've typed since focusing the field, and right after accepting it waits for the next keystroke, so a second Tab moves on, as Tab does whenever there's no ghost. Esc hides it until you type again. ↓ and ↑ make it follow the active suggestion. On a touch screen a tap on the ghost accepts it, and the key cap isn't shown.

        The ghost is drawn over the input in its font, in the input's text color at 40 % (--datalynx-ghost-color), and stops at the field's edge. In a right-to-left field it follows on the left, and Arabic letters join once accepted. Accepting plays a short sweep; with reduced motion the value just appears. Screen readers don't hear the ghost, which the list of suggestions already offers, but hear the value it puts in. The key cap's label is the text tabKey, "Tab" in every language.

        Long lists

        Any list longer than a batch, 50 options by default, starts with a batch of rows, and more are shown a few at a time as you scroll, so the scrollbar shrinks smoothly instead of jumping and a datalist of thousands opens at once. Searching still covers every option, and the arrow keys go past the rows shown so far. batch-size sets how many rows the list works with at a time: the rows shown first, and how far ahead it searches. batch-size="0" renders everything at once.

        This one has 5,000 suggestions, in batches of 20. Press ↓ and scroll, or type "4999" to find one near the end.

        A missing or invalid batch-size uses DataLynx.defaultBatchSize, 50 unless you change it.

        Live changes

        The datalist stays the source of truth. Add, remove or change its options with the usual DOM methods, and the suggestions follow, also while the popover is open, where the active suggestion stays active. batch-size is live too, and so is the property of the same name. Open the popover, then click the buttons: they don't take focus, so it stays open.

          Theming

          The stylesheet draws a neutral popover meant to sit well in most pages, in light and dark, in the same look as Platypicker's. Change it with --datalynx-* variables, set on data-lynx or any ancestor. Move the controls, then open the popover to see them; the CSS tab follows.

          The default colors switch between light and dark with the page's color-scheme, so a page with a dark theme should say so. Use light-dark() to give your own colors for both.

          Class plugs

          Every element Datalynx creates has a fixed dlx-* class you can style, and the input it enhances gets dlx-input. Each part also has a plug: extra classes added next to the fixed one, empty by default, for dressing the popover in a framework's own classes. The state plug itemActive is on the row the arrow keys are on, while it is.

          Plugs are global, and elements read them when they are created. The elements already in the page are enhanced the moment datalynx is imported, so fill the plugs in a module of their own that imports classes.js, and import it first. The field below runs in a frame of its own, so its plugs don't reach the rest of this page.

          Localization

          Each field follows its nearest lang attribute. Search ignores case and accents the way the language does: try "kase" in the German field. Datalynx has three texts (the number of matches that screen readers hear once typing pauses, a strict input's message, and a ghost's key cap), and their translation loads the first time a field needs it, so an English page loads none.

          It ships translations for 22 languages, the same as Platypicker's: Arabic, Bengali, Bulgarian, Chinese (simplified and traditional), French, German, Hindi, Indonesian, Italian, Japanese, Korean, Marathi, Polish, Portuguese, Russian, Spanish, Tamil, Telugu, Turkish, Urdu and Vietnamese. A regional tag uses its language (de-AT is German), and any other language stays English.

          The translations are plain objects in src/languages/, one file per language. Import one to bundle it, or register texts of your own in DataLynx.languages, which win over Datalynx's. The text has plural forms, picked by the language's own rules.

          Right to left

          In a right-to-left page or element (dir="rtl") the popover lines up with the input's right edge, and images, icons and subtexts swap sides.

          Browser support

          Datalynx needs anchor positioning (with anchor-scope), the popover attribute and the CSS Custom Highlight API.

          • Chrome and Edge 135 and later.
          • Firefox, current releases, with no flags.
          • Safari 27 and later, on the Mac and on iPhone.

          Without support, <data-lynx> does nothing: the input keeps its list, and the browser's own datalist works as it always did, so forms keep working everywhere.

          So far Datalynx has been checked on the desktop, in Chrome, in Firefox 161 and in WebKit 27.2 (the engine of Safari, through Playwright). Safari itself and phones haven't been tested yet, and on phones Datalynx shows the same popover as on the desktop: a layout for phones is still to come.

          A few things to keep in mind:

          • Only a direct child input is enhanced: <data-lynx><input list>. Its datalist can be anywhere in the same document or shadow root.
          • <data-lynx> is display: contents, so size and place the input as you would without it.
          • While enhanced, the input has no list attribute and has autocomplete="off"; see The browser's datalist. Selectors of yours on input[list] no longer match it.

            About

            Datalynx is an open-source web component that enhances inputs with a datalist. It's developed on GitHub, and will be published to npm with its first release. Bug reports and feature requests go to GitHub issues, and pull requests are welcome, including corrections to the translations.

            The family

            Datalynx is a sibling of Platypicker, which does the same for a <select>: a searchable popover in the same look, with the same search, long lists and languages. An input takes free text and a datalist only suggests, so the two differ where that matters: here focus stays in the input, which is a combobox. What they share lives in Burrowkit, their common core, down to this page's header, navigation and code panels.
